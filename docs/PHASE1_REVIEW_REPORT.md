## 5. Deviations from the raw source data (all documented in `docs/IMPLEMENTATION_AUDIT.md`)

1. **3 connector waypoint corrections** (`e01`, `e02`, `e05`) — the raw curated JSON routes these through their own domain group's label text. The renderer applies a small, explicitly-commented override (`src/data/curatedView.ts`) that redraws only these 3 polylines through the layout's existing gaps/padding gutters. Source, target, type, and label are unchanged; verified against the geometry validator with no new overlaps or crossings introduced.
2. **2 logo-strategy overrides** (`VEN-MICROSOFT`, `VEN-SERVICENOW`) — the data declares `simple-icons` for both, but simple-icons has no Microsoft/Azure or ServiceNow mark. Both render as typographic wordmarks instead, per `CLAUDE.md`'s own fallback rule. Also isolated to `src/data/curatedView.ts`.

Neither deviation touches any node/group position, size, canonical fact, or catalogue reference — both are presentation-layer routing/logo corrections, fully covered by the deterministic validator and unit tests.

## 6. Unresolved visual deviation

One narrow, environment-specific rendering artifact remains unresolved: in this sandboxed headless-Chromium environment (software rendering, no GPU), the wrapped second line of one gap card's subtitle ("Target POS / SCO **platform**") occasionally paints with a distorted glyph for the letter "p" ("nlatform") when the canvas is under its pan/zoom CSS transform at certain fractional zoom scales.

Investigated in depth: the DOM text content and computed `font-size` are confirmed correct (verified via `getComputedStyle`/`textContent`); it reproduces with the edge/connector layer hidden (ruling out a connector visually overlapping the text); it is not caused by `-webkit-line-clamp` (reproduces with and without it); layer-promotion hints (`transform: translateZ(0)`, `will-change: transform`) did not reliably resolve it once retested against the full app rather than a minimal isolated page. It is a paint-only artifact of this container's software text rasterizer under a scaled ancestor transform, not a data, logic, or layout defect — the validator and all 63 automated checks pass because they inspect the DOM/computed styles, which are correct. It is not expected to reproduce in a standard GPU-accelerated desktop browser. No fix is shipped for it because every attempted fix was verified (via a fresh rebuild, not a stale cache) to have no actual effect once retested end-to-end, and shipping an inert "fix" would be dishonest about the app's real behavior.

## 7. Statement on later phases

Phases 2–5 (catalogue/systems/suppliers/evidence pages, TO FIND management, search, domain deep-dive views, editing, authentication, RLS, and Postgres/Supabase persistence) were **deliberately not built**. The application currently has exactly one route's worth of UI: the light app shell plus the curated Total Architecture canvas, drawer, pan/zoom, and hover highlighting. No catalogue browsing UI, no filters, no search, no auth, and no database exist in this codebase yet, per the Phase 1 stop-gate in `CLAUDE.md` and `02_START_HERE.md`.
